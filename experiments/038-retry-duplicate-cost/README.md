# 038 — 재시도·중복 처리 비용

[실험 목차](../README.md) · [037 장당 구조화 비용](../037-measurement-sheet-unit-cost/README.md)

**재현 PASS. H1·H2 지지, H3 기각.** 실행 전 결정은 2026-11-27에 먼저 썼고, 가설·판정 기준은 실행 뒤 바꾸지 않았다. 설계 변경 1건은 아래에 기록했다.

같은 측정지가 여러 번 처리될 때 Textract·Bedrock을 얼마나 더 쓰는지, 방지 규칙이 얼마나 막는지를 합성 이벤트 시뮬레이션으로 계산한다. AWS를 호출하지 않는다. 모든 확률·시간은 **가정값**이다.

## 설계 변경 기록

- **2026-11-27, 첫 실행 직후**: 첫 실행에서는 규칙마다 난수 흐름이 달라 측정지 모집단(사진 여부, 페이지 수, 중복 전달·재구조화 발생)이 규칙마다 조금씩 달랐다(이상값 비용이 규칙마다 0.020110~0.020175 USD로 다름). 규칙 비교를 공정하게 하려고 모집단은 (시드, 확률 단계)마다 한 번만 뽑아 세 규칙·세 timeout에 똑같이 쓰고, 처리 시간·Bedrock 결과만 따로 뽑도록 바꿨다. 가설과 판정 기준은 바꾸지 않았다. 바꾸기 전 판정도 H1·H2 지지, H3 기각으로 같았다.

이상값(필요 최소) 장당 비용은 0.02046 USD다. B는 이상값보다 **싸다**: 정당한 재구조화 요청을 처리하지 않았기 때문이다.

**확률 단계별 A의 추가 OCR (timeout 30 / 60 / 120초)**: 낮게 +13.9% / +5.5% / +5.1%, 기본 +21.3% / +11.9% / +11.5%, 높게 +32.2% / +18.9% / +18.4%. 모든 조건에서 DLQ는 0건이었다.

- **H1 지지**: A·timeout 30초에서 OCR이 이상값보다 21.3% 많았다. 시드 3개 합계로 원인별 추가 OCR 페이지는 재구조화 때의 OCR 반복 1,593, timeout 초과 재전달 1,217, SQS 중복 전달 137 순이었다.
- **H2 지지**: B는 중복·재전달로 생긴 추가 OCR을 99.9~100% 막았지만, 담당자 재구조화 요청 1,545건을 **모두** 막았다(오판 100%).
- **H3 기각**: C는 오판 0건이고 OCR은 이상값과 같았지만, A 대비 비용은 timeout 30초에서만 0.856이었고 60·120초에서는 0.923·0.926으로 10% 절감에 못 미쳤다. timeout이 길면 A의 재전달 자체가 줄어 C가 아낄 몫이 작다.
- C도 이상값보다 1% 비싸다(0.02068 대 0.02046). Bedrock 잘못된 출력 재시도(원인 3)는 어떤 규칙으로도 막지 않았다.

**월 비용 영향(기본 확률, timeout 30초, A → C)**: 장당 0.00349 USD 차이 → 작업량 보통(2,200장/월) 7.67 USD, 크게(11,000장/월) 38.36 USD.

## 해석

- 추가 OCR의 두 큰 원인은 **재구조화 때 OCR을 처음부터 다시 하는 것**과 **visibility timeout이 처리 시간보다 짧을 때의 재전달**이다. 앞의 것은 OCR 결과 저장(C)으로, 뒤의 것은 timeout 조정으로 줄어든다. timeout을 30초에서 60초로 늘리는 것만으로 A의 추가 OCR이 21.3%에서 11.9%로 줄었다. 처리 시간 분포(특히 2페이지 사진 + Bedrock 재시도의 꼬리)를 보고 timeout을 정하거나, 처리 중 `ChangeMessageVisibility`로 연장해야 한다.
- 파일 해시만으로 막는 B는 비용 지표로는 가장 좋아 보이지만, 정당한 재구조화를 조용히 버린다. 비용 지표만 보고 규칙을 고르면 안 되는 사례다. 키에 요청 종류를 넣고 OCR 결과를 재사용하는 C가 비용과 정확성을 함께 만족했다.
- InfraFit 규칙 후보(후보): "SQS visibility timeout < 처리 시간 p95" → 재전달 비용 검토. "중복 방지 키가 요청 종류를 구분하지 않음" → 오판 위험.

## 가정·제외·한계

- 모든 확률(중복 1%, 스로틀 5%, 잘못된 출력 3%, 재구조화 10%)과 처리 시간 분포는 가정이다. 실제 Textract·Bedrock 지연을 측정하지 않았다.
- 스로틀링된 호출은 과금하지 않고, 잘못된 출력은 과금한다고 가정했다. 응답 도중 끊긴 호출의 과금 방식은 확인하지 않았다.
- 메시지 삭제는 어느 처리든 성공하면 바로 된다고 단순화했다(재수신 뒤 이전 수신 핸들로 삭제할 때의 동작은 모형화하지 않음). 워커 동시성 한도, 큐 대기 시간, 처리 중 visibility 연장은 넣지 않았다.
- B·C의 "처리 중" 판정은 DB 고유 키 선점이 즉시·정확하다고 가정했다. 실제로는 워커가 죽으면 선점이 남아 다시 처리되지 않을 수 있다(만료 시간 필요).
- 금액은 037 기준 요율(Tables 0.015 USD/페이지, Haiku 4.5 토큰 보통 0.006 USD/회, Global 요율)이다. S3·SQS 요청은 넣지 않았다.

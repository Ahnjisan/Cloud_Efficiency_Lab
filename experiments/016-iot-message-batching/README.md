# 016 — IoT Core 메시지 묶음 전송의 계량·비용·지연

[실험 목차](../README.md) · [최종 연구 보고서](../../FINAL-REPORT.md) · [IoT Core 학습 노트](../../studies/aws/iot-core/README.md)

**계산 재현 PASS. 가설 H1~H3 모두 지지.** 센서 측정값을 N개씩 묶어 보낼 때 IoT Core의 계량 메시지 수, 월 비용, 추가 지연을 결정적으로 계산했다. 요율은 [서울 리전 Price List 사본](../../references/aws-price-list-apn2-2026-11-13.json)(AWSIoT 게시일 2026-10-03)을 읽는다. AWS 호출은 없다.

## 실행 전 결정

| 항목 | 내용 |
|---|---|
| 질문 | 측정값을 묶어 보내면 IoT Core 비용은 얼마나 줄고, 그 대가로 지연은 얼마나 늘어나는가? |
| 가설 H1 | 200 B 페이로드를 20건씩 묶으면 메시지·규칙·액션 비용(연결 제외)이 개별 전송보다 **90% 이상** 줄어든다. 90% 미만이면 기각한다. |
| 가설 H2 | 묶음으로 인한 최대 추가 지연은 `(N−1) × 측정 주기`다. 한 조합이라도 다르면 기각한다. |
| 가설 H3 | 묶음 크기가 5 KB 경계를 넘는 N에서 메시지당 계량이 1→2로 뛰어 절감이 계단식으로 꺾인다. 경계를 넘어도 계량이 그대로면 기각한다. |
| 기준선 | 개별 전송(N=1) |
| 바꿀 변수 | 센서 수 {10, 100, 1000}, 측정 주기 {1, 10, 60}초, 페이로드 {100, 200, 1000, 4000} B, 묶음 N {1, 5, 10, 20, 25, 26, 50}, 5 KB 정의 {5,000 B, 5,120 B}, 레코드당 구분자 {0, 1} B |
| 통제 조건 | 30일(2,592,000초), 모든 센서 상시 연결, 규칙 1개·액션 1개, 무료 제공량·세금 제외, 공개 On-Demand 요율 |
| 데이터 | 합성 작업량, 결정적 계산. 시드 없음 |
| 반복 | 결정적 계산이라 1회. `result.json`과 재실행 결과가 같은지 테스트로 확인 |

## 결과

### 기준 작업량 (센서 100대, 10초, 200 B, 5 KB = 5,120 B)

| 구성 | 계량 메시지 | 메시지 | 규칙 | 액션 | 연결 | 월 합계 | 1,000건당 | 최대 추가 지연 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 개별 전송 | 25,920,000 | 31.10 | 4.67 | 4.67 | 0.41 | **40.85 USD** | 0.001576 USD | 0초 |
| 20건 묶음 | 1,296,000 | 1.56 | 0.23 | 0.23 | 0.41 | **2.44 USD** | 0.000094 USD | 190초 |
| 20건 묶음 + Basic Ingest | 1,296,000 | 0 | 0.23 | 0.23 | 0.41 | **0.88 USD** | 0.000034 USD | 190초 |

- **H1 지지**: 메시지·규칙·액션 비용이 **95.0%** 줄었다(연결 포함 총액은 94.0%).
- **H2 지지**: 유효한 972개 조합 모두에서 최대 추가 지연이 `(N−1) × 주기`였다. 이 값은 정의에 가까운 항등식이며, 네트워크·디바이스 처리 지연은 포함하지 않는다.
- **H3 지지**: 200 B × 26건 = 5,200 B는 두 정의 모두에서 2단위로 계량됐다. 센서 1,000대·60초 주기에서 월 합계는 N=25일 때 6.84 USD, N=26일 때 9.33 USD로 **묶음을 늘렸는데 비용이 36% 증가**했다.
- **5 KB 정의의 영향**: 레코드당 구분자 1 B가 붙으면 25건 묶음(5,025 B)은 5,000 B 정의에서 2단위, 5,120 B 정의에서 1단위였다. 경계 바로 아래에 묶음 크기를 맞추면 실제 계량이 어느 쪽인지에 따라 비용이 두 배가 된다.

### 효과가 작은 경우

| 조건 | 결과 |
|---|---|
| 페이로드 4,000 B | 5건 묶음(20,000 B → 4단위)도 메시지·규칙·액션 비용이 **20%만** 줄었다. 20건 묶음은 5건과 같은 계량이다(16단위 × 1,296,000). 이미 5 KB에 가까운 메시지는 묶어도 거의 줄지 않는다. |
| 페이로드 4,000 B × 50건 | 200,000 B가 최대 메시지 크기(128 KB)를 넘어 36개 조합이 무효 처리됐다. |
| 연결 비용 | 묶음과 무관하다. 센서 1,000대·60초 주기에서는 50건 묶음 후 월 합계 6.84 USD 중 연결이 4.15 USD(61%)를 차지한다. |

## 해석

페이로드가 5 KB보다 훨씬 작고 전송 빈도가 높을수록 묶음 효과가 크다. 판정에 필요한 핵심 입력은 **디바이스별 평균 메시지 크기, 전송 주기, 토픽별 허용 지연**이다. 이 중 허용 지연이 정해지지 않으면 비용이 크게 줄어도 변경 후보로 올리지 않는다. 경보·제어 토픽은 묶음 대상이 아니다.

## 가정·제외·한계

- MQTT 헤더·토픽 이름이 계량 크기에 포함되는지는 확인하지 않았다. 페이로드 크기만으로 계산했다.
- 실제 디바이스의 메모리, 배터리, 재전송, 묶음 중 장애로 잃는 데이터는 계산하지 않았다.
- 규칙·액션은 메시지 크기 5 KB 단위로 계량된다는 요금 페이지 설명에 따라 계량 메시지 수와 같게 계산했다.
- 30일 고정, 상시 연결 가정이다. 간헐 연결 디바이스는 연결 비용이 더 작다.
- Firehose 이후 단계의 비용은 [017](../017-firehose-buffer-small-files/README.md)·[019](../019-pipeline-unit-cost/README.md)에서 다룬다.

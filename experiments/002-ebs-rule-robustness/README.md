[사전에 고정한 정책과 가설](policy.md) · [합성 입력과 사후 정답 근거](cases.json) · [출력 원본](result.json) · [실행 로그](../infrafit-execution-log.json)

Windows 11에서 Python 3.14.7 표준 라이브러리로 실행했다. 저장소 루트에서 `py -3 -B experiments/002-ebs-rule-robustness/evaluate.py`를 실행한다. 종료 코드 0이다. 001의 두 규칙을 그대로 호출하고 중복 ID 및 001과의 ID 중첩을 검사했다. 평가용 신규 볼륨 11건 중 9건은 사후 라벨이 확정됐고 2건은 미확정이다.

| 지표 | A · 연결 상태 | B · 소유·복구 근거 |
|---|---:|---:|
| TP / FP / FN / TN | 3 / 4 / 1 / 1 | 1 / 1 / 2 / 3 |
| 정밀도 · 확정 경보 기준 | 42.9% | 50.0% |
| 즉시 재현율 · 확정 낭비 4건 | 75.0% | 25.0% |
| 보류 · 전체 11건 | 0건 | 4건 (36.4%) |
| 초기 검토 대기 · 경보+보류 | 9건 | 6건 |

B의 보류 4건은 확정 낭비 1, 확정 정상 1, 미확정 2건이다. 확정 낭비 보류는 즉시 재현율의 분모에 포함했다. A는 미확정 2건을 경보했지만 오탐으로 세지 않았다. B는 보존 의무가 있는 볼륨의 오탐을 줄였다. 그러나 연결된 중복 볼륨과 폐기된 복구 계획을 현재 계획으로 믿은 경우는 놓쳤다. 반대로 기록이 완전하다고 표시됐지만 실제 의존성이 있던 볼륨에는 오탐이 남았다. 사후 조사에서 낭비였던 오래된 기록은 보류됐다.

가설의 오탐 감소는 이 표본에서 확인됐고, 즉시 탐지율 저하도 관찰됐다. 정밀도·재현율은 반례를 의도적으로 배치한 합성 데이터의 결과다. 후속 질문은 기록의 유효 시점을 어떻게 독립적으로 확인하고, 보류에 필요한 검토 시간을 어떻게 측정할 것인가이다. [팀 검토 흐름](../../studies/methods/ebs-waste-review-workflow.md)

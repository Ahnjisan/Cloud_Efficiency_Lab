# 실험 안내 — 실행 전 설계와 재현 기록

[연구 방법](../studies/methods/research-methodology.md)을 실제 기록으로 연결한다. 아래 기준은 향후 실행을 설계할 때 사용한다. [실험 목록](README.md)에는 수행한 실험만 등록한다.

## 실행 전 결정

1. 질문, 반증 가능한 가설, 기준선과 바꿀 변수, 통제할 조건을 정한다. 예를 들어 동일 요청 분포·동일 성공 처리량에서 p99 200 ms 및 오류율 1% 이하를 만족하는 구성의 비용 차이를 묻는다.
2. 데이터는 실제 관측·공개·합성으로 구분한다. 출처·접근 권한·라이선스, 라벨의 생성 주체·누락, 시간 순서 분할과 누출 방지 기준을 적는다.
3. OS, 커널, 런타임·도구 버전, 하드웨어·리전, 입력 기간, 설정, 시드, 워밍업, 반복 횟수와 실행 순서를 고정하거나 차이를 기록한다. 오류와 중단을 포함할 집계 규칙과 원본 위치를 정한다.
4. 예상 비용에는 요율·시간·단위·포함 범위를, 실제 청구 비교에는 기간·할인·갱신 지연과 원본 행을 적는다. 업무량·품질 조건이 다르면 절감 비교를 보류한다.

비용 비교표에는 성공 요청당 비용(포함 비용 합계 ÷ 성공 요청 수), p95·p99, 성공 처리량, 오류율을 함께 둔다. 가상 비용 $20에서 10,000건이 성공하면 성공 1,000건당 $2다. 스토리지·전송·관측을 제외했으면 양쪽에 같은 방식으로 표시한다. 데이터 버전과 튜닝에 사용한 기간도 기록해 최종 평가 기간을 보호한다.

## 향후 유료 환경의 안전 조건

AWS 작업은 계정·리전·서비스·자원 수·권한, 예상 비용 상한, 최대 지속 시간, 안전 중단 신호, 정리 방법을 정한 뒤 승인 범위에서만 진행한다. 예산 알림과 별도로 종료 시한 및 정리 확인 책임을 명시한다. 컴퓨팅 종료 후 스토리지·스냅샷·공인 주소·로그 등 잔존 비용을 별도 점검한다. 비밀 값과 개인정보를 원본 로그·실험 기록에 공개하지 않는다.

## 실행 후 기록

실제 명령과 설정, 원본 결과·오류, 반복별 수치와 집계 방식, 관측·추정의 차이, 재현 범위와 한계를 남긴다. 동일 조건이 깨졌거나 일부만 재현한 경우 그 범위를 밝힌다. 이번 문서는 설계 지침이다.

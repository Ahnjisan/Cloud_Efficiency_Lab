# 로컬 검증 001 — EBS 낭비 탐지 규칙

[탐지 평가 문서](../../studies/methods/ec2-ebs-waste-detection-evaluation.md)의 가상 볼륨 8개로 두 규칙의 판정과 집계를 재현했다. 기록이 충돌할 때 규칙 B가 보류를 우선하는지 별도 검사했다. 출력에는 판정, 이유, 다음 담당자를 포함한다. 팀의 실제 검토와 변경 승인 절차는 [EBS 권고 검토 흐름](../../studies/methods/ebs-waste-review-workflow.md)에 있다.

## 재현 방법

저장소 루트에서 다음 명령을 실행한다. Windows의 Python 3.14.7로 검증했으며 외부 패키지는 필요하지 않다. 입력과 기대값은 [검증 스크립트](verify_rules.py)에 따로 정의돼 있다. 8개 볼륨에 대한 두 규칙의 판정·이유·다음 담당자 16세트와 집계를 자동 대조한다. 하나라도 어긋나면 오류로 종료한다.

```powershell
py -3 -B experiments/001-ebs-waste-rules/verify_rules.py
```

## 실행 결과

| 가상 입력 8건 기준 | 규칙 A · 연결 여부 | 규칙 B · 기록 확인 |
|---|---:|---:|
| 탐지한 낭비(TP) | 2 | 2 |
| 오탐(FP) | 1 | 0 |
| 미탐(FN) | 1 | 1 |
| 정상으로 확인된 경보 없음(TN) | 2 | 3 |
| 정답 미확정 · 채점 제외 | 2 | 2 |
| 전체 경보 | 5 | 2 |
| 전체 판단 보류 | 0 | 2 |
| 초기 검토 대기(경보 + 보류) | 5 | 4 |

규칙 B는 미확정 두 건을 보류했다. 연결된 중복 볼륨은 두 규칙이 모두 놓쳤다. 기준 8건과 별도로, **복구가 필요하다는 기록이 있는 경우**와 **사용 종료·의존성 없음이라는 기록이 있는 경우**에 각각 충돌 표시를 넣었다. 두 경우 모두 `hold | conflicting-records | orders`를 반환했다. 이 두 검사는 우선순위 검증이며 위 집계에 포함하지 않았다.

실행 마지막 줄은 `PASS: 8 baseline volumes and 2 conflict precedence checks`였다. 이 검증은 구조화된 합성 입력을 사용한다. 실제 운영 기록에서 충돌을 찾아내는 과정, 팀의 검토 시간, 실제 낭비율·절감액은 측정하지 않았다.

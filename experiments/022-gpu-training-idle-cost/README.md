# 022 — GPU 학습의 유휴 비용과 잔존 비용 (선택 실험)

[실험 목차](../README.md) · [최종 연구 보고서](../../FINAL-REPORT.md) · [SageMaker 학습 노트](../../studies/aws/sagemaker/README.md)

**계산 재현 PASS. H1·H2 지지.** 이상탐지 모델을 SageMaker로 옮긴다고 가정하고, GPU 노트북을 상시 켜 두는 경우, 근무 시간에만 켜는 경우, CPU 노트북과 GPU 학습 작업을 분리하는 경우의 월 비용을 계산했다. 요율은 [서울 Price List 사본](../../references/aws-price-list-apn2-2026-11-13.json)(AmazonSageMaker 게시일 2026-11-13, AmazonS3 2026-11-09)을 읽는다.

## 실행 전 결정

| 항목 | 내용 |
|---|---|
| 질문 | 실제 학습 시간에 비해 GPU를 켜 둔 시간이 비용을 얼마나 좌우하며, 컴퓨팅을 멈춘 뒤 무엇이 남는가? |
| 가설 H1 | 월 실제 학습 16시간에서, GPU 노트북(ml.g4dn.xlarge) 상시 실행 비용은 "CPU 노트북 근무 시간 실행 + GPU 학습 작업" 비용의 **10배 이상**이다. |
| 가설 H2 | 컴퓨팅을 모두 멈춘 뒤에도 노트북 ML 스토리지와 S3 아티팩트 비용이 남는다(0보다 크다). |
| 기준선 | GPU 노트북 상시 실행(720시간) |
| 바꿀 변수 | 운영 방식 3종, 월 실제 학습 시간 {4, 16, 40, 80, 160}, 노트북 스토리지 {20, 50} GB, 학습 인스턴스 {g4dn.xlarge, g5.xlarge} |
| 통제 조건 | 한 달 720시간, 근무 시간 22일 × 8시간 = 176시간, S3 아티팩트 20 GB, 학습 볼륨 50 GB(학습 시간만큼 비례 과금), 공개 On-Demand 요율, Spot·프리 티어 제외 |
| 데이터 | 결정적 계산. 시드 없음 |

## 실행

```powershell
cd experiments/022-gpu-training-idle-cost; py -3 -B calculate.py > result.json; py -3 -B test_calculate.py
```

## 결과 (노트북 스토리지 50 GB, g4dn.xlarge)

| 월 실제 학습 | GPU 노트북 상시 | GPU 노트북 근무 시간만 | CPU 노트북 + GPU 학습 작업 | 상시 ÷ 분리 |
|---:|---:|---:|---:|---:|
| 4시간 | 660.80 USD | 167.94 USD | 23.06 USD | 28.7배 |
| 16시간 | 660.80 USD | 167.94 USD | 34.07 USD | **19.4배** |
| 40시간 | 660.80 USD | 167.94 USD | 56.08 USD | 11.8배 |
| 80시간 | 660.80 USD | 167.94 USD | 92.76 USD | 7.1배 |
| 160시간 | 660.80 USD | 167.94 USD | 166.13 USD | 4.0배 |

- **H1 지지**: 학습 16시간에서 19.4배였다. 다만 학습 시간이 80시간 이상이면 10배 아래로 내려간다. "10배"는 학습 비중이 작을 때만 성립한다.
- 상시 실행에서 실제 학습에 쓴 GPU 시간 비율은 16시간 기준 **2.2%**다.
- 근무 시간 GPU 노트북과 학습 작업 분리의 손익분기는 월 학습 **164시간**이다. 근무 시간의 대부분을 학습에 쓴다면 GPU 노트북을 근무 시간에만 켜는 방식도 비용상 차이가 거의 없다.
- **H2 지지**: 컴퓨팅을 모두 멈춘 뒤 남는 비용은 노트북 스토리지 20 GB일 때 월 3.69 USD, 50 GB일 때 8.48 USD였다(S3 아티팩트 20 GB 포함).
- g5.xlarge 학습 작업은 시간당 1.54625 USD로 g4dn.xlarge보다 71% 비싸다. g5가 같은 학습을 얼마나 빨리 끝내는지 측정하지 않았으므로 **어느 인스턴스가 싼지는 판단을 보류**한다.

## 해석

GPU 유휴 비용의 판정 입력은 **GPU 자원이 켜져 있던 시간**과 **실제 학습 작업 시간**이다. 둘의 비율이 낮을수록 분리 효과가 크다. 노트북 안에서 장시간 학습을 돌리고 있다면 상시 실행이 낭비가 아닐 수 있으므로, 커널 활동이나 GPU 사용률 없이 상태 기간만 보고 후보로 올리지 않는다.

## 가정·제외·한계

- 학습 작업의 초 단위 과금, 시작·종료 오버헤드, 데이터 다운로드 시간, 관리형 Spot 할인은 확인하지 않아 제외했다.
- Colab 비용·성능과의 비교는 범위 밖이다.
- 노트북 자동 중지 설정(수명 주기 스크립트 등)의 동작은 확인하지 않았다. "근무 시간만" 시나리오는 정확히 176시간 켜진다고 가정했다.
- 학습 시간과 모델 품질의 관계는 계산에 없다.

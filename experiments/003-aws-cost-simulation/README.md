# 003 — EC2·EBS 비용·구성 시뮬레이션

가설은 EC2 요율이나 운영시간을 줄여도 EBS 잔존 비용, 기존 약정, 업무량·품질 조건 때문에 의사결정이 달라진다는 것이다. [기존 가상 사례](../../studies/methods/ec2-ebs-case-study.md)와 [ADR](../../studies/methods/ec2-capacity-decision.md)을 기준으로, 별도의 [합성 시나리오](scenarios.json)를 실행했다. 단위는 가상 USD, 720시간, 가상 리전이다. 인스턴스 유형 이름과 단가는 모델용이다.

## 독립 기준선과 새 결과

기존 ADR 수치를 먼저 식으로 대조했다. EBS는 (100+50+25)×$0.08=$14.00, 약정은 720×$0.12=$86.40이다. 보조 작업이 약정을 소비하는 기준·축소·피크 확장의 비용은 각각 $100.40+720×$0.04=$129.20, $100.40, $100.40+120×($0.10+$0.04)=$117.20이다. 003의 새 입력은 다른 단일 볼륨 조건도 포함한다.

| 새 시나리오 | 변경 전 → 후 USD | 판정과 근거 |
|---|---|---|
| A · 컴퓨팅 유형 변경 | 144.00 → 72.00 | 후보. 같은 업무량과 가상 품질 통과 조건 |
| B · EC2 중지와 EBS 유지 | 152.00 → 8.00 | 보류. 잔존 EBS $8 및 서비스 품질 미확인 |
| C · 고정 약정 | 94.40 → 94.40 | 유지. 약정액과 EBS 비용 동일 |
| D · 업무량 변화 | 152.00 → 152.00 | 보류. 1,000건당 $152 → $76이지만 총 업무량이 다름 |
| E · 품질 미확인 | 152.00 → 80.00 | 보류. $72 차이만으로 채택 불가 |
| F · gp2에서 gp3 및 성능 추가 | 82.00 → 86.00 | 유지. 후보 EBS $8 + IOPS $5 + Throughput $1 |
| G · 볼륨 용량 누락 | 152.00 → 미계산 | 보류 |
| H · 운영시간 360시간 | 152.00 → 80.00 | 후보. 같은 업무량·품질이라는 가상 전제 |

## 재현과 적용 범위

Windows 11, Python 3.14.7에서 `py -3 -B experiments/003-aws-cost-simulation/simulate.py`를 실행한다. [원본 JSON 출력](result.json)과 [시도별 실행 로그](../infrafit-execution-log.json)를 참고한다. 첫 실행은 B의 품질 입력과 기대 판정이 어긋나 실패했다. 중지 구성을 품질 미확인으로 바로잡은 후 종료 코드 0을 확인했다.

검사는 금액·절감률, 단위 비용, 0시간, 약정 일부 커버, 음수·누락·비유한 값, 중복 비용 키를 포함한다. EBS는 구성별로 볼륨 ID가 필요하며 누락 또는 중복 시 합산 전에 보류한다. 동일 ID 두 건의 후보 비용은 미계산이고, 사양이 같아도 서로 다른 ID 두 건의 비용은 $160.00으로 확인했다. Decimal로 각 비용 행을 센트 단위로 반올림해 합산한다. EBS는 월 전체 보존을 가정하고, 추가 성능은 기본 제공분을 뺀 양을 입력받는다. 추가 성능의 구성 가능 여부는 별도 검증이 필요하다. 약정 모형은 동일한 사용이 있는 시간에 단일 인스턴스와 단일 약정만 적용한다. 여러 상품의 시간대별 우선순위, 저장 일할 계산, 세금·전송·스냅샷·운영비는 범위 밖이다.

[공식 Savings Plans 적용](https://docs.aws.amazon.com/savingsplans/latest/userguide/sp-applying.html)과 [EBS 학습 자료](../../studies/aws/ebs/README.md)의 구조를 대조했으며, AWS 실제 요율이나 청구 데이터는 사용하지 않았다. 다음 질문은 약정 공유와 전송·스냅샷 비용을 추가해도 후보 순서가 유지되는가이다.

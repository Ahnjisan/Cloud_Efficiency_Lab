# 026 — 과금 단위 올림·최소 과금의 일반식

[실험 목차](../README.md) · [누수 패턴 방법 노트](../../studies/methods/cost-leak-patterns.md) · [기준 시나리오](../scenarios/README.md)

**재현 PASS. H1 기각, H2 지지.** 서비스마다 다른 올림 규칙(IoT 5 KB, WebSocket 32 KB, Guardrails 1,000자, Fargate 1분 최소, Athena 10 MB 최소)을 `과금량 = max(최소, ⌈x / u⌉ × u)` 한 식으로 다루고, 평균 크기로 계산한 추정이 크기 분포로 계산한 값과 얼마나 다른지 합성 분포로 확인했다.

## 실행 전 결정

| 항목 | 내용 |
|---|---|
| 질문 | 평균 크기·평균 시간만 알 때 과금량을 얼마나 틀리게 추정하는가? 낭비율을 미리 알 수 있는 조건은? |
| 가설 H1 | 변동계수(CV) 0.5 이상인 경우의 절반 이상에서, 평균 기반 추정이 분포 기반 과금량보다 10% 이상 작다. |
| 가설 H2 | 평균이 단위의 절반 미만이면(최소치가 단위보다 큰 Fargate 제외) CV와 무관하게 낭비율이 50%를 넘는다. |
| 데이터 | 합성. 사례 13개 × CV {0, 0.5, 1.0}, 로그정규 분포, 사례마다 20만 표본, 시드 26 + 사례 번호 |
| 단위 | [service_pack.py](../scenarios/service_pack.py)의 `UNITS`. IoT 5 KB는 5,120 B로 계산(5,000 B 여부 미확인) |
| 요율 | [2026-11-15 사본](../../references/aws-price-list-apn2-2026-11-15.json)의 AWSIoT `APN2-Messages` (시나리오 확인용) |
| 지표 | 항목당 과금 단위 수, 평균 기반 오차 = 평균 기반 / 분포 기반 − 1, 낭비율 = 1 − 실사용 합 / 과금량 합 |

## 실행


- **H1 기각**: 10% 이상 과소 추정은 CV ≥ 0.5인 26개 중 8개였다. 과소 추정은 **평균이 단위 경계나 최소치 바로 아래에 있고 분산이 클 때**(4.8 KB/5 KB, 30 KB/32 KB, 800자/1,000자, 45초/60초)만 크게 나타났다. 평균이 경계를 조금 넘으면(6 KB) 오히려 17~20% **과대** 추정했다. 평균이 단위보다 훨씬 작거나(200 B) 훨씬 크면(300초, 50 MB) 평균만으로 충분했다.
- **H2 지지**: 평균이 단위의 절반 미만인 6개 사례(IoT 200 B, WebSocket 4 KB × CV 3개)는 모두 낭비율이 50%를 넘었다(87~96%). 최소치가 단위보다 큰 Athena·Fargate는 검사에서 뺐지만, 같은 방향으로 평균이 최소치보다 훨씬 작은 Athena 2 MB(80%)와 Fargate 20초(67%)도 낭비율이 컸다.
- **시나리오 ① 확인**: 측정값 200 B를 1건씩 보내면 계량 메시지는 2,592만 건(31.10 USD)인데, 바이트 합계를 5 KB로 나눈 용량 기반 추정은 101만 건(1.22 USD)으로 **25.6배 과소**다. 20건을 묶으면 1.28배, 26건(5,200 B)을 묶으면 경계를 넘어 1.97배로 다시 벌어진다.

## 해석

- 올림 낭비를 판정하는 규칙은 평균 크기가 아니라 **"평균 / 단위" 비율과 분포의 퍼짐**을 함께 봐야 한다. 실용 규칙: 평균이 단위의 0.5배 미만이면 분포 없이도 낭비율 50% 초과로 판정할 수 있다(공식 단위 + 실험 확인). 평균이 단위의 0.8~1.0배 구간이면 분포 없이 금액을 추정하지 말고 판단 보류로 둔다.
- 용량(GB) 기반 비용 추정은 건수로 계량되는 서비스에서 크게 틀린다. 건수와 건당 크기를 함께 받아야 한다.

## 가정·제외·한계

- 분포는 로그정규 하나만 썼다. 이봉 분포(작은 메시지와 큰 메시지가 섞임)는 다루지 않았다.
- IoT 5 KB를 5,120 B로 계산했다. 5,000 B이면 4.8 KB(4,915 B) 사례의 CV 0 결과도 1단위로 같지만 경계 근처 결과는 달라진다.
- Lambda 1 ms 올림, 노드 시간 올림은 [029](../029-fixed-cost-scheduling/README.md)와 [031](../031-container-runtime-cost/README.md)에서 다룬다.

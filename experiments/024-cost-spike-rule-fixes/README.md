# 024 — 비용 급증 규칙(R-COST-1) 보완과 작은 급증 재평가

[실험 목차](../README.md) · [021 합성 평가](../021-daily-cost-spike-detection/README.md) · [023 실제 계정 점검](../023-real-cost-spike-check/README.md) · [InfraFit 운영 규칙](../../infrafit/README.md#운영-규칙-r-fh-2-r-ath-12-r-sm-1-r-cost-1)

**평가 재현 PASS. H1·H2·H3 모두 성립, 채택 규칙에 따라 V4를 InfraFit 기본값으로 바꿨다.** 아래 "실행 전 결정"은 코드를 고치거나 데이터를 다시 돌리기 전에 작성했고, 결과를 본 뒤 바꾸지 않았다. 실제 데이터는 023에서 받은 원본을 다시 썼으므로 추가 AWS 비용은 없다.

## 실행 전 결정

| 항목 | 내용 |
|---|---|
| 배경 | 023에서 R-COST-1이 실제 청구 410일에 오탐 27건을 냈다. 원인은 (1) 월 고정 요금의 2월 일수 효과(+10.7%)가 10% 하한을 넘은 것, (2) 평소 0인 세금이 월 첫날마다 경보가 된 것이다. 021은 급증 크기 +50% 이상만 평가해 작은 급증(+10~30%)의 재현율을 모른다 |
| 질문 A | 아래 세 가지 보완을 더하면 023의 실제 오탐이 사라지면서 021의 급증 탐지 성능을 유지하는가? |
| 질문 B | 작은 급증(+10~30%)을 현재 규칙과 보완 규칙은 얼마나 잡는가? |
| 보완 1 · 세금 분리 | `Tax` 서비스 시계열은 판정하지 않고, 합계 시계열에서도 뺀다 |
| 보완 2 · 최소 증가액 | 경보 조건에 "기준 중앙값보다 최소 0.50 USD/일 이상 높음"을 더한다(임시값, 데이터를 보기 전에 정함) |
| 보완 3 · 달력 보정 | 하한 비교에 `기준 창의 월 일수 중앙값 ÷ 현재 달 일수`(1 미만이면 1)를 곱한다. 월 고정 요금이 짧은 달에 하루 단위로 커지는 만큼만 허용한다. MAD 조건은 그대로 둔다 |
| 비교 변형 | V0 현재 규칙 / V1 = V0 + 세금 분리 / V2 = V0 + 최소 증가액 / V3 = V0 + 달력 보정 / V4 = 세 보완 모두 |
| 데이터 | (a) 023의 실제 원본(저장소 밖, 결과는 비식별 요약만) (b) 021 평가용 시드 101~120(급증 +50~300%) (c) 같은 생성기에서 급증 크기만 +10~30%로 바꾼 시드 201~220. 합성 시계열에는 날짜를 2025-01-01부터 붙인다 |
| 평가 | 021과 같은 사건 단위 재현율, 정상일 30일당 오탐, 탐지 지연. 준비 기간 56일 이후만 센다. 실제 데이터는 023과 같이 모든 경보를 오탐으로 본다 |
| 가설 H1 | V4는 023 실제 데이터의 서비스별 오탐을 0건으로 만든다 |
| 가설 H2 | V4의 급증(+50% 이상) 재현율은 V0보다 2%p 넘게 떨어지지 않고, 오탐/30일은 V0보다 높지 않다 |
| 가설 H3 | V0의 작은 급증(+10~30%) 재현율은 50% 미만이다 |
| 채택 규칙 | H1과 H2가 모두 성립하면 V4를 InfraFit의 기본값으로 바꾼다. 하나라도 성립하지 않으면 기본값은 그대로 두고, 각 보완을 선택 옵션으로만 남긴다. 작은 급증 결과(H3)는 채택 판단에 쓰지 않는다 |
| 조정 금지 | 0.50 USD, k=3, 10%, 28일은 이 실험에서 바꾸지 않는다 |

- **H1 성립**: V4는 실제 데이터의 서비스별 오탐을 27건에서 **0건**으로 줄였다.
- **H2 성립**: 큰 급증에서는 다섯 변형의 결과가 완전히 같았다. 합성 시계열은 하루 10~50 USD 규모라 0.50 USD 하한이 걸리지 않았고, 월 고정 요금 패턴이 없어 달력 보정도 판정을 바꾸지 않았다.
- **H3 성립**: 작은 급증(+10~30%)은 현재 규칙과 보완 규칙 모두 **21.5%**만 잡았다. 잡힌 경우에도 평균 지연이 0.45일로 길었다. 이 규칙은 큰 급증용이며, 작은 상승은 사실상 놓친다.
- **채택**: H1·H2가 모두 성립해 V4를 [thresholds.json](../../infrafit/thresholds.json)의 기본값으로 바꿨다: `cost.excluded_services=["Tax"]`, `cost.min_abs_increase_usd=0.5`, `cost.calendar_allowance=true`.

## 해석

- **이 계정에서는 최소 증가액(V2) 하나만으로도 오탐이 모두 사라졌다.** 금액이 하루 1센트 수준이라서다. 실제 프로젝트 규모에서는 그렇지 않다. 월 고정 요금의 2월 증가분은 `요금 × (1/28 − 1/31) ≈ 요금 × 0.0035`/일이라, 월 145 USD가 넘는 고정 요금이면 0.50 USD 하한을 넘는다. InfraFit 테스트에서 월 3,000 USD 고정 요금으로 확인했다. 하한만 켜면 2월에 14일 경보가 나고, 달력 보정을 켜야 사라진다. 그래서 세 보완을 함께 채택했다.
- **작은 급증은 이 규칙의 범위 밖이다.** 하한을 낮추면 일수 효과(10.7%)와 주말 변동이 다시 오탐이 된다. 작은 상승은 급증 규칙이 아니라 예측 잔차 누적이나 주·월 단위 비교 같은 다른 방법으로 다룰 문제로 남긴다.

## 가정·제외·한계

- 0.50 USD는 데이터를 보기 전에 정한 임시값이다. 실제 프로젝트의 일별 비용 규모에 맞춰 다시 정해야 한다.
- 달력 보정은 짧은 달에 하한을 넓힌다. 그래서 사용량 기반 비용의 작은 급증은 2월에 조금 덜 잡힐 수 있다. 합성 데이터에서는 차이가 없었다.
- 세금 외의 월초 일괄 청구(지원료, 약정료 등)는 이 계정에 없어 평가하지 않았다.
- 실제 데이터는 급증이 없는 작은 계정 하나다.

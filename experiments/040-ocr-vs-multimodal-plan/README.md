# 040 — Textract + Bedrock vs Bedrock 이미지 직접 입력 (계획)

[실험 목차](../README.md) · [037 장당 구조화 비용](../037-measurement-sheet-unit-cost/README.md) · [025 실제 과금 확인 실험의 승인·정리 절차](../025-billing-rule-probe/README.md)

**상태: 계획, 미실행.** 실제 AWS 호출(Textract, Bedrock)이 필요하므로 이 문서는 계획만 담는다. 코드를 실행하지 않았고 AWS를 호출하지 않았다. 실행하려면 아래 승인 체크리스트를 저장소 소유자가 모두 확인해야 한다.

## 질문

손글씨 측정지에서 측정값을 공통 형식으로 옮길 때, 세 가지 방식의 **숫자 정확도**와 **장당 비용**은 어떻게 다른가?

| 안 | 흐름 |
|---|---|
| P1 | Textract AnalyzeDocument(Tables) → 추출 텍스트·표를 Bedrock(텍스트)으로 구조화 |
| P2 | Bedrock 멀티모달에 측정지 이미지를 직접 넣어 구조화 (OCR 없음) |
| P3 | P1의 Textract 결과와 이미지를 함께 Bedrock에 넣어 구조화 |

[037](../037-measurement-sheet-unit-cost/README.md)에서 장당 비용은 Textract 종류가 가장 크게 바꿨다(기준 구성에서 Textract 69%). Textract를 빼는 P2가 정확도를 지키면 비용 구조가 바뀐다. 그 정확도는 계산으로 알 수 없어 실제 호출이 필요하다.

## 실행 전 결정 (초안 — 실행 승인 때 확정)

| 항목 | 내용 |
|---|---|
| 가설 H1 | P2의 숫자 필드 정확도는 P1보다 낮지 않다(차이 −1%p 이내). |
| 가설 H2 | P2의 장당 비용은 P1의 50% 이하다(같은 모델 기준). |
| 가설 H3 | P3는 소수점·부호 오독률이 셋 중 가장 낮다. |
| 판정 기준 후보 | 프로덕트 목표 "손글씨 오독 1% 이하"를 숫자 필드 기준 합격선 후보로 쓴다. 30장으로는 1% 수준을 통계적으로 확정하기 어렵다(필드 수가 수백 개여도 신뢰구간이 넓다) → 결과는 "목표 근처인지"를 보는 예비 판정으로만 쓴다 |
| 지표 | 숫자 필드 정확도(정답과 완전 일치 비율), 소수점 오독률(자릿수·소수점 위치 오류), 부호 오독률(+/−, 공차 기호), 필드 누락률, 장당 비용(실제 청구 사용량 기준과 응답 토큰 기준 둘 다), 처리 시간 p50·p95 |
| 모델 | Claude Haiku 4.5와 Sonnet 4.5(서울에서 쓸 수 있는 프로필 확인 후 확정). 데이터 위치 요구가 있으면 Global이 아닌 지역·리전 내 프로필을 쓰고 그 요율을 먼저 확인한다(현재 **확인 필요**) |
| 반복 | 장마다 안별 3회(LLM 출력 변동 확인), 온도 0 |
| 통제 | 같은 이미지(해상도·압축 고정), 같은 출력 스키마·프롬프트(P1·P3는 OCR 블록만 추가), 같은 리전·모델 버전 |

## 합성 측정지 30장 준비

- 팀원이 **손으로 직접 쓴 가상 측정지** 30장. 실제 고객·회사·도면 자료를 쓰지 않는다. 회사명·고객사명 칸은 비우거나 "가상"으로 쓴다.
- 양식 3종 × 10장(표 칸 크기·항목 순서가 다른 가상 양식). 장마다 측정값 15~25개, 공차(±, +/−0.0x), 소수점 0~3자리, 음수 일부 포함.
- 필기자 3명 이상(글씨체 다양성), 펜 2종, 일부러 흐린 칸·겹친 숫자·지운 흔적을 30장 중 6장에 넣는다.
- 촬영: 스마트폰 2종, 조명 2조건, 정면/약간 기울임. 장당 이미지 1개(JPEG, 긴 변 2,000 px 이하로 고정).
- **정답표**: 쓰기 전에 값을 먼저 정하고(스프레드시트), 쓴 뒤 2명이 대조 확인. 정답표는 이미지와 같은 ID로 연결한다.
- 이미지와 정답표는 저장소 밖에 둔다(저장소에는 생성 절차와 집계 결과만).

## 예상 AWS 비용과 근거

| 항목 | 계산 | 예상 USD |
|---|---|---:|
| Textract Tables (P1·P3) | 30장 × 1페이지 × 2안 × 3회 × 0.015 USD/페이지(서울, [rates_manual.json](../037-measurement-sheet-unit-cost/rates_manual.json)) | 2.70 |
| Bedrock 텍스트 (P1, Haiku 4.5) | 30 × 3회 × (입력 3,000 × 1.00 + 출력 600 × 5.00) / 100만 | 0.54 |
| Bedrock 이미지 (P2, Haiku 4.5) | 30 × 3회 × (이미지 약 1,600 + 프롬프트 1,000 토큰 입력, 출력 600) — 이미지 토큰 수는 **가정**(확인 필요) | 0.50 |
| Bedrock 결합 (P3, Haiku 4.5) | 30 × 3회 × (이미지 1,600 + OCR 3,000 + 1,000 입력, 출력 600) | 0.77 |
| Sonnet 4.5로 같은 반복 | 위 Bedrock 항목 × 3 | 5.45 |
| S3 임시 저장·요청 | 30개 이미지, 하루 보관 | < 0.01 |
| **합계(Haiku + Sonnet)** | | **약 10 USD** |

예산 상한 **15 USD**. 요율은 Global 교차 리전 기준이며, 리전 내 프로필을 쓰면 실행 전에 그 요율로 다시 계산한다. 무료 제공량과 세금은 제외.

## 위험

- 오독 1%를 30장으로 확정할 수 없다(표본 부족) → 예비 판정으로만 쓰고, 합격선 근처면 표본을 늘리는 2단계 계획을 따로 승인받는다.
- Global 프로필은 요청이 국외 리전에서 처리될 수 있다. 합성 자료라 위험은 낮지만, 실제 운영 결론으로 옮길 때는 처리 위치 조건을 맞춰 다시 측정해야 한다.
- 모델 응답 변동으로 정확도가 실행마다 달라질 수 있다(3회 반복으로 범위 기록).
- 청구 반영이 하루 이상 늦어 실제 비용 확인이 늦다([025](../025-billing-rule-probe/README.md)에서 24시간 시점 미반영).

## 유지 시간·중단 조건·정리

- **유지 시간**: 실행 2시간 이내. S3 임시 버킷은 실행 당일 삭제.
- **중단 조건**: (1) 누적 예상 비용이 10 USD 도달, (2) 같은 오류 2회, (3) 스로틀링으로 재시도가 장당 3회 초과, (4) 예상하지 못한 자원 생성 발견 → 즉시 멈추고 기록.
- **정리**: S3 객체·버킷 삭제, IAM 임시 역할·정책 삭제, CloudShell 임시 파일 삭제, 남은 자원 0건 확인 후 기록(025와 같은 절차). Textract·Bedrock은 남는 자원이 없다.

## 승인 체크리스트 (실행 전 저장소 소유자 확인)

- [ ] 계정·리전(ap-northeast-2)·사용 서비스(S3, Textract, Bedrock) 확인
- [ ] Bedrock 모델 접근 권한과 사용할 추론 프로필(Global/지역/리전 내), 그 요율 확인
- [ ] 예산 상한 15 USD, 중단 조건 4가지 동의
- [ ] 합성 측정지 30장과 정답표 준비 완료, 실제 자료가 섞이지 않았음 확인
- [ ] 실행 시간대(2시간)와 정리 책임자 지정
- [ ] 결과 기록 범위: 이미지·응답 원문은 저장소 밖, 저장소에는 집계와 절차만

# 007 — InfraFit 통합 분석 가능성

[실험 목차](../README.md) · [최종 연구 보고서](../../FINAL-REPORT.md) · [읽기 전용 MVP](../../infrafit/README.md)

가설은 Plan 변경, 비용 행, Pod 리소스 설정과 워크로드 품질의 출처를 보존하면, 작은 오프라인 분석으로 후보·유지·보류를 구분할 수 있다는 것이다. 기준은 003의 비용 차이만 보는 경우다. 이번 비교는 Terraform 결측, 중복 비용과 품질 기준을 추가한다.

## 입력과 데이터 계약

| 입력 | 출처와 연결 |
|---|---|
| Terraform 변경 | [004 추출 결과](../004-terraform-evidence/result.json)의 address로 합성 사례가 참조 |
| 비용 | [003 계산 결과](../003-aws-cost-simulation/result.json)의 EC2·EBS 행 또는 006의 노드 비용. 003의 가격 근거는 Terraform 주소와 전후 인스턴스 유형이 모두 일치할 때 적용한다. 중복 사례는 두 출처가 같은 청구 키를 보낸다고 가정 |
| Kubernetes | [006 정적 결과](../006-kubernetes-resource-efficiency/result.json)의 Pod Requests·Limits와 노드 용량 |
| 컨테이너·워크로드 | [007 합성 입력](cases.json)의 CPU(m), 메모리(MiB), I/O(MiB/s), p95·p99(ms), 성공 처리량(req/s), 오류율(%). Docker·클러스터 실측은 없었다. |

결과는 실험·환경·워크로드·자원 식별자, 시간 범위와 출처, 현재·후보 지표, 가상 단가 범위, 비용, 결측, 판정과 다음 검증 조건을 남긴다. 연결 키와 관측 범위는 사례에서 명시적으로 부여한다. 실제 데이터의 리소스 식별자 매핑과 시간 정렬은 미검증이다. D는 노드 비용 비교만 보여주는 가상 대안이며 EC2·EBS 비용에 합산하지 않는다.

## 재현과 결과

저장소 루트에서 `py -3 -B experiments/reproduce-infrafit.py`를 실행하면 003·004·006 출력을 먼저 저장하고 007 결과를 생성한다. 선행 단계가 실패하면 007을 실행하지 않는다. 저장된 선행 출력으로 007만 실행하려면 `py -3 -B experiments/007-infrafit-feasibility/integrate.py`를 사용한다. Windows 11, Python 3.14.7에서 종료 코드 0을 확인했다. [출력 JSON](result.json) · [결과표](results.md) · [실행 로그](../infrafit-execution-log.json)

검사는 필수 사례 6건에 더해 p99 누락, 음수 p99, 무한 처리량, 100% 초과 오류율, 가격 근거와 다른 전후 유형·자원 주소를 포함했다. 잘못된 품질 수치는 결측과 별도로 기록한다. 가격 근거가 일치하지 않으면 두 비용을 보류하고, 후보 비용 행에 중복이 있으면 후보 합계를 보류한다. 낮은 비용도 품질을 위반하면 유지한다. 결과는 합성 계약 검증이다. 다음 질문은 실제 청구 식별자와 관측 시간대가 불일치할 때 잘못된 결합을 어떻게 차단할 것인가이다.

최초 성공 후 D의 노드 용량 근거를 출력에 추가해 다시 실행했다. 실행 로그에는 두 시도가 남아 있으며, 원본 JSON은 최종 실행의 stdout이다.

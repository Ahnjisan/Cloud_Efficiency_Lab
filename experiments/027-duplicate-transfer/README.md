# 027 — 같은 데이터의 중복 전송

[실험 목차](../README.md) · [누수 패턴 3](../../studies/methods/cost-leak-patterns.md#3-같은-데이터의-중복-전송) · [기준 시나리오 ①](../scenarios/iot-pipeline-agent.json)

**재현 PASS. H1·H2 지지.** 시나리오 ①(IoT 수집 → 실시간·배치 → AI 에이전트)에서 측정값 하나가 거치는 경로를 따라가며 각 단계가 무엇을 얼마나 과금하는지 셌다. 중복 경로가 있는 설계(D0)와 없앤 설계(D1)를 비교했다.

## 실행 전 결정

| 항목 | 내용 |
|---|---|
| 질문 | 같은 데이터가 여러 단계를 거칠 때 과금되는 양은 원본의 몇 배이고, 어느 단계가 금액을 정하는가? |
| 가설 H1 | D0에서 바이트 단위로 과금되는 양(Firehose 과금 GB + 로그 수집 GB + Athena 스캔 GB + NAT 처리 GB)이 원본의 10배 이상이다. |
| 가설 H2 | 중복 경로를 없애면(D1) 이 경로의 월 비용이 30% 이상 준다. |
| D0 (중복) | IoT 규칙 2개(목적지마다 1개), 실시간 Lambda가 측정값마다 500 B 로그, 에이전트 도구가 요청마다 하루치 원본을 NAT로 내려받음 |
| D1 (중복 제거) | 규칙 1개에 액션 2개, Lambda는 호출마다 100 B 요약 로그, 에이전트는 Athena 결과만 읽고 S3는 게이트웨이 엔드포인트 경유 |
| 공통 | 디바이스 100대, 10초마다 200 B, 30일. Firehose 5 KB 올림, IoT 메시지·규칙·액션 5 KB 계량, Lambda 512 MB·호출당 50 ms, 에이전트 월 3,000건 × Athena 질의 2회 × 50 MB |
| 요율 | [2026-11-15 사본](../../references/aws-price-list-apn2-2026-11-15.json) |

## 실행

```powershell
cd experiments/027-duplicate-transfer

```

## 결과

원본(측정값 바이트 합)은 월 **4.83 GB**다.

| 단계 | D0 과금 양 (원본 대비) | D1 과금 양 (원본 대비) |
|---|---:|---:|
| Firehose 과금 GB(5 KB 올림) | 123.6 GB (25.6배) | 123.6 GB (25.6배) |
| CloudWatch 로그 수집 | 12.07 GB (2.5배) | 2.41 GB (0.5배) |
| Athena 스캔 | 293 GB (60.7배) | 293 GB (60.7배) |
| NAT 처리 | 482.8 GB (100배) | 0 |
| **합계** | **911 GB (188.8배)** | 419 GB (86.8배) |

| 월 비용 (USD) | D0 | D1 |
|---|---:|---:|
| IoT 메시지 | 31.10 | 31.10 |
| IoT 규칙 | 9.33 | **4.67** |
| IoT 액션 | 9.33 | 9.33 |
| Firehose 수집 | 4.45 | 4.45 |
| Lambda (측정값마다 호출) | 15.98 | 15.98 |
| 로그 수집 + 첫 달 저장 | 9.55 | **1.91** |
| Athena | 1.43 | 1.43 |
| NAT 처리 | 28.49 | **0.00** |
| **합계** | **109.67** | **68.88 (−37.2%)** |

- **H1 지지**: D0의 바이트 과금 양은 원본의 188.8배였다. 가장 큰 배수는 NAT(에이전트가 요청마다 하루치 원본을 다시 내려받음, 100배)와 Athena(같은 최근 데이터를 반복 스캔, 61배)였다.
- **H2 지지**: 중복 경로 세 가지(규칙 중복, 측정값별 로그, NAT 재다운로드)를 없애 37.2%가 줄었다. 줄어든 40.79 USD 중 NAT가 28.49 USD(70%)였다.
- **배수와 금액은 다르다**: Athena는 원본의 61배를 스캔하지만 1.43 USD였고, NAT는 100배에 28.49 USD였다. 같은 GB라도 단계마다 GB 요율이 0.0049(Athena, 5 USD/TB)에서 0.76(로그 수집)까지 150배 차이 난다. 로그는 원본의 2.5배만 받는데 9.17 USD였다.

## 해석

- 중복 전송 규칙은 "같은 데이터가 몇 번 지나가는가"보다 **"GB 요율이 높은 단계(로그 수집 0.76, NAT 0.059)를 몇 번 지나가는가"** 로 판정해야 한다.
- InfraFit 규칙 후보: (1) 같은 토픽 필터를 가진 IoT 규칙이 2개 이상 → 액션을 한 규칙으로 합치는 것을 검토(공식 자료, 규칙 수 × 메시지 수로 금액 계산 가능). (2) 측정값·요청마다 본문 전체를 로그로 남기는 함수 → 로그 수집 GB / 처리 건수가 크면 검토(실험 확인). (3) 사설 서브넷 + NAT + S3 게이트웨이 엔드포인트 없음 → [028](../028-nat-vs-vpc-endpoint/README.md)과 같은 규칙.
- Lambda 측정값별 호출(15.98 USD)도 묶음으로 줄일 수 있지만([Lambda 노트 추가 절](../../studies/aws/lambda/README.md)), IoT 규칙의 Lambda 액션은 메시지마다 호출하므로 SQS 등 묶음 지점을 넣는 설계 변경이 필요하다. 이 실험에서는 바꾸지 않았다.

## 가정·제외·한계

- 에이전트가 하루치 원본을 내려받는 동작, 로그 줄 크기는 가정이다. 실제 배수는 코드와 로그 형식에 달렸다.
- IoT 연결 시간, S3 PUT·저장, 로그 보관 2개월째 이후는 넣지 않았다(보관 기간은 [034](../034-observability-cost/README.md)).
- Firehose의 5 KB 올림과 IoT 메시지 계량은 [026](../026-billing-unit-rounding/README.md)·[016](../016-iot-message-batching/README.md)에서 다룬 묶음으로 줄일 수 있으며 두 설계 모두 묶지 않은 상태다.

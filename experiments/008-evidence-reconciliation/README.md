# 008 — 청구·변경·피크 관측 대사

[실험 목차](../README.md) · [최종 연구 보고서](../../FINAL-REPORT.md) · [MVP에서 실행](../../infrafit/README.md)

**합성 데이터 재현 PASS.** 007의 최종 판정 앞에 놓이는 데이터 연결을 검증한다. [가상 청구 행](billing.json), [Terraform 주소와 자원 ID 매핑 및 후보 비용](changes.json), [피크 관측](peaks.json)을 별도로 입력한다. 금액은 같은 가상 평가 구간의 USD다. Terraform CLI나 AWS API 없이 Python 표준 라이브러리로 실행한다.

저장소 루트에서 `py -3 -B experiments/008-evidence-reconciliation/reconcile.py`를 실행한다. [결과 원본](result.json)

| 조건 | 결과 |
|---|---|
| 피크 관측이 아직 없는 주문 서비스 | 보류 |
| 같은 평가 구간의 청구 $20과 피크 p99 180ms가 늦게 도착 | 기준 $120 → 후보 $100, 변경 검토 후보 |
| 전체 청구 입력을 다시 수신 | 결과 동일, 이중 집계 없음 |
| 같은 청구 행 ID에 서로 다른 금액 | 해당 자원 보류 |
| 청구 자원 ID 누락 또는 과거 구간의 피크 관측만 존재 | 보류 |
| 동일 구간에 Terraform 주소 매핑이 중복 | 해당 주소 보류 |
| 같은 자원·기간에 현재 구성이나 다른 후보의 피크 관측만 존재 | 해당 후보 보류 |
| 후보와 일치한 피크 관측의 p99가 음수·비유한 값이거나 누락 | 보류 |
| 후보가 $30 낮지만 피크 p99 250ms | 유지 |

비교 기준 p99 200ms는 실험용이다. 피크 관측은 자원 ID·평가 구간·후보 구성 ID가 모두 일치하고 평가 시점까지 도착한 값 하나를 사용한다. 재현 명령은 같은 자원의 두 후보가 서로 다른 관측값으로 판정되는 반례도 검사한다. 자원 ID 매핑, 후보 구성 ID와 후보 비용은 주어진 합성 입력이다. 실제 Plan의 주소와 청구 행을 자동 매핑하는 방법, 비용 배분 및 실제 청구와의 대사는 후속 검증 범위다. [007 통합 판정](../007-infrafit-feasibility/README.md)

# EC2·EBS 가상 데이터 — 낭비 탐지 규칙 평가

**연구 질문.** EBS 볼륨의 미연결 여부에 소유자와 복구 기록을 더하면 불필요한 경보를 줄일 수 있는가? 그때 어떤 낭비는 여전히 탐지하지 못하는가?

[EC2·EBS 가상 연구 사례](ec2-ebs-case-study.md)의 데이터·복구·용도 미확인 볼륨에서 출발해 평가용으로 8개 볼륨을 구성했다. 평가 단위는 **같은 시점의 볼륨 1개**다. EC2는 연결 여부와 워크로드 용도를 설명하는 맥락으로 쓰며, 이 평가는 EC2 컴퓨팅 과다 할당을 다루지 않는다.

## 1. 입력과 정답을 분리한다

두 규칙은 같은 가상 입력을 받는다. 정답은 규칙 입력 시점의 기록을 그대로 복사하지 않고, 별도의 가상 사후 조사 결과로 부여한다. 사후 조사에서는 소유자 확인, 이관 완료, 데이터·복구 의존성, 보존 의무를 대조한다. 서비스와 복구 요건을 유지하면서 볼륨 비용을 피할 수 있다고 확인하면 **낭비**, 볼륨이 현재 서비스나 복구에 필요하면 **정상**, 조사 후에도 증거가 부족하면 **정답 미확정**이다. 미확정은 평가 데이터의 상태이고, **판단 보류**는 규칙의 출력이다.

| 가상 볼륨 | EC2 연결 | 규칙이 볼 수 있는 소유자·운영 기록 | 별도 사후 조사와 정답 |
|---|---|---|---|
| `vol-data` | 연결 | 주문 서비스 소유, 운영 데이터 볼륨 | 실제 서비스 읽기·쓰기 의존 확인 → **정상** |
| `vol-recovery` | 미연결 | 운영팀 소유, 유효한 복구 계획에 명시 | 현재 요구 복구 경로에 필요 → **정상** |
| `vol-unknown` | 미연결 | 소유자 없음, 복구 기록 누락 | 소유권·복구 의존성 확인 실패 → **미확정** |
| `vol-migrated` | 미연결 | 주문팀 소유, 이관 완료 및 보존·복구 의존성 없음으로 기록 | 이관 대상 검증과 기존 볼륨 폐기 요건 충족 → **낭비** |
| `vol-temp` | 미연결 | 배치팀 소유, 임시 작업 종료 및 보존·복구 의존성 없음으로 기록 | 작업 완료 및 재실행에 원본이 필요 없음을 확인 → **낭비** |
| `vol-stale` | 연결 | 배치 EC2에 연결, 소유팀 확인 | 이전 배치의 중복 데이터. 새 경로 검증과 기존 마운트·복구 의존성 해소 확인 → **낭비** |
| `vol-os` | 연결 | 운영 EC2의 부팅 볼륨, 소유팀 확인 | 인스턴스 기동에 필요 → **정상** |
| `vol-transfer` | 미연결 | 이관팀 소유, 복구·보존 기록이 서로 충돌 | 담당팀 기록 불일치가 해소되지 않음 → **미확정** |

## 2. 두 규칙의 판정

- **규칙 A · 연결 상태만 확인.** 미연결이면 경보, 연결돼 있으면 경보 없음.
- **규칙 B · 소유자와 복구 기록 확인.** 연결돼 있으면 이 규칙의 탐지 범위 밖이므로 경보 없음. 미연결이면 소유자·용도·보존·복구 기록에 판정에 필요한 정보가 빠졌거나 서로 충돌하는지 먼저 확인한다. 누락이나 충돌이 있으면 판단 보류. 기록이 충분하고 일치하면, 유효한 운영·복구 목적이 확인된 볼륨에는 경보 없음. 소유자가 확인되고 사용이 끝났으며 보존·복구 의존성이 없다고 확인된 볼륨에는 경보를 낸다. 어느 조건도 확인되지 않으면 판단을 보류한다.

두 규칙의 경보는 추가 검토 대상이다. 실제 삭제 여부에는 별도의 확인이 필요하다.

| 볼륨 | 정답 | 규칙 A | 규칙 B |
|---|---|---|---|
| `vol-data` | 정상 | 경보 없음 · TN | 경보 없음 · TN |
| `vol-recovery` | 정상 | 경보 · FP | 경보 없음 · TN |
| `vol-unknown` | 미확정 | 경보 · 채점 제외 | 판단 보류 · 채점 제외 |
| `vol-migrated` | 낭비 | 경보 · TP | 경보 · TP |
| `vol-temp` | 낭비 | 경보 · TP | 경보 · TP |
| `vol-stale` | 낭비 | 경보 없음 · FN | 경보 없음 · FN |
| `vol-os` | 정상 | 경보 없음 · TN | 경보 없음 · TN |
| `vol-transfer` | 미확정 | 경보 · 채점 제외 | 판단 보류 · 채점 제외 |

## 3. 오탐·미탐과 보류를 따로 집계한다

확정 6건(낭비 3건, 정상 3건)으로만 혼동 행렬을 계산한다. 이 데이터에서는 두 규칙 모두 확정 건에서 보류하지 않았다.

| 지표 | 규칙 A | 규칙 B |
|---|---:|---:|
| 탐지한 낭비(TP) | 2 | 2 |
| 오탐(FP) | 1 | 0 |
| 미탐(FN) | 1 | 1 |
| 정상으로 확인된 경보 없음(TN) | 2 | 3 |
| 정밀도 = TP ÷ (TP + FP) | 2/3 ≈ 66.7% | 2/2 = 100% |
| 재현율 = TP ÷ (TP + FN) | 2/3 ≈ 66.7% | 2/3 ≈ 66.7% |
| 오탐률 = FP ÷ (FP + TN) | 1/3 ≈ 33.3% | 0/3 = 0% |

미확정 2건에 대해서는 A가 둘 다 경보를 냈고, B는 둘 다 보류했다. 이 2건의 경보를 오탐으로 집계하거나 보류를 정상으로 집계할 근거는 없다. 전체 8건에서 A는 경보 5건·경보 없음 3건·보류 0건, B는 경보 2건·경보 없음 4건·보류 2건이다. B의 전체 보류율은 2/8 = 25%다. 후속 데이터에서 정답이 확정된 건에도 보류가 생기면 정답별 보류 건수를 따로 공개한다. 즉시 탐지율을 계산할 때는 경보를 낸 확정 낭비만 분자에 넣고, 보류된 확정 낭비도 분모에 포함한다.

## 4. 해석과 한계

[EBS 권고 검토 흐름](ebs-waste-review-workflow.md)에서 각 판정을 팀의 검토·승인·사후 확인 절차에 연결한다.

[로컬 검증 기록](../../experiments/001-ebs-waste-rules/README.md)에서 이 8건의 판정·집계 재현과 별도의 충돌 우선순위 검사를 확인할 수 있다.

B는 복구용 볼륨의 오탐 1건을 제거했다. 연결된 중복 볼륨은 두 규칙 모두 놓쳐 재현율은 그대로다. 연결 여부를 탐지의 첫 조건으로 삼았기 때문이다. 소유자·복구 기록이 오래되거나 잘못됐을 때의 오류는 이 8건에 포함돼 있지 않다. 따라서 100% 정밀도는 이 가상 표의 확정 경보 2건에 한정된다.

이 사례는 수기 검산이 가능한 합성 평가다. 실제 낭비 발생률이나 절감액은 측정하지 않았다. 지표의 정의는 [비용 이상탐지](anomaly-detection.md), 자원과 보존 조건은 [EBS 비용 산정](../aws/ebs/README.md)에서 이어서 확인할 수 있다.

- `vol-recovery`가 보존 기한을 넘겼지만 대체 복구 경로가 확인되지 않았다면 어떤 근거가 더 필요한가?
- `vol-stale` 같은 연결 볼륨을 조사할 때 낮은 I/O 외에 어떤 운영 기록이 필요한가?

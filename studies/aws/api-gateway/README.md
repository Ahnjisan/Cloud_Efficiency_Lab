# Amazon API Gateway 비용 산정 01 — HTTP·REST 요청과 WebSocket 메시지·연결 분

[AWS 서비스 목차](../README.md) · [누수 패턴 방법 노트](../../methods/cost-leak-patterns.md)

> 같은 기능을 HTTP API, REST API, WebSocket API 중 무엇으로 만드느냐에 따라 월 비용은 얼마나 달라지는가? 클라이언트가 10초마다 상태를 묻는 폴링과 서버가 밀어 주는 WebSocket 중 어느 쪽이 싼가?

요율은 **AWS Price List 서울 리전 온디맨드 공개 요율**([2026-11-15 사본](../../../references/aws-price-list-apn2-2026-11-15.json), AmazonApiGateway 게시일 2026-11-12)이고, 작업량은 가상 값입니다. 무료 제공량은 제외합니다.

## 1. 과금 단위

| API 종류 | 항목 | 계량 | 서울 요율 |
|---|---|---|---|
| HTTP API | 요청 | 요청 건수. 요금 페이지 예시는 **512 KB 단위**로 큰 요청을 여러 건으로 셈 | 처음 3억 건 1.23 USD/100만, 초과 1.11 |
| REST API | 요청 | 요청 건수 | 처음 3.33억 건 3.50 USD/100만, 다음 6.67억 3.19, 다음 190억 2.71, 초과 1.72 |
| REST API | 캐시 | 캐시 크기별 시간 | 0.5 GB 0.02 USD/시간 |
| WebSocket | 메시지 | 보내고 받는 메시지. **32 KB 단위로 계량**, ping/pong은 계량하지 않음 | 처음 10억 건 1.14 USD/100만, 초과 0.94 |
| WebSocket | 연결 시간 | 연결된 분 | 0.285 USD/100만 연결 분 |

- 응답 스트리밍은 추가 요금이 없고, 요금 페이지 예시는 10 MB 단위로 계산합니다.
- HTTP API의 512 KB 단위는 요금 페이지의 계산 예시에만 나오고 Price List 행에는 없습니다(`missing`에 기록).

## 2. 가상 예제

**(가) 같은 요청 3,000만 건/월**

| 구성 | 계산 | 월 비용 |
|---|---|---:|
| HTTP API | 30 × 1.23 | 36.90 USD |
| REST API | 30 × 3.50 | 105.00 USD |
| REST API + 0.5 GB 캐시 | 105.00 + 0.02 × 730 | 119.60 USD |

REST API에만 있는 기능(API 키·사용량 계획, 요청 검증, 캐시 등)을 쓰지 않는다면 차이 68.10 USD는 기능 없이 내는 비용입니다.

**(나) 클라이언트 1,000개가 10초마다 상태 확인(30일 상시 연결)**

| 구성 | 월 계량 | 계산 | 월 비용 |
|---|---:|---|---:|
| HTTP API 폴링 | 요청 2.592억 | 259.2 × 1.23 | **318.82 USD** |
| WebSocket 서버 푸시(10초마다 1메시지) | 메시지 2.592억 + 연결 4,320만 분 | 259.2 × 1.14 + 43.2 × 0.285 | **307.80 USD** |
| WebSocket, 상태가 바뀔 때만 푸시(1분에 1번) | 메시지 4,320만 + 연결 4,320만 분 | 43.2 × 1.14 + 43.2 × 0.285 | 61.56 USD |

- 같은 빈도로 보내면 WebSocket이 크게 싸지 않습니다. 절감은 **보내는 횟수를 줄일 때** 생깁니다. 변경이 있을 때만 보내면 메시지 요금이 1/6이 됩니다.
- 메시지가 40 KB면 32 KB 단위로 2건이 됩니다. 큰 상태 전체를 매번 보내는 대신 변경분만 보내면 계량 건수가 줄어듭니다.
- 연결 분 요금은 메시지가 없어도 쌓입니다. 사용하지 않는 탭·기기가 연결을 유지하면 그대로 과금됩니다.

## 3. 낭비가 생기는 조건과 판단 근거

1. **기능을 쓰지 않는 REST API**: 사용 중인 REST 전용 기능 목록이 판단 자료입니다. 목록을 확인하지 못하면 HTTP API 전환은 **판단 보류**입니다.
2. **짧은 주기 폴링**: 클라이언트 수 × 폴링 주기로 요청 수를 계산하고, 실제 데이터 변경 빈도와 비교합니다.
3. **큰 메시지·큰 요청**: 32 KB(WebSocket), 512 KB(HTTP API 예시) 경계를 넘는 비율을 봅니다. 접근 로그에 크기 필드를 남겨야 알 수 있습니다.
4. **유휴 연결**: 연결 수와 메시지 수의 비율로 유휴 연결을 추정합니다. 유휴 시간 제한(idle timeout)과 재연결 비용을 함께 봅니다.

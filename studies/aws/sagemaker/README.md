# SageMaker 비용 산정 01 — 학습·노트북·엔드포인트와 유휴 비용

[AWS 서비스 목차](../README.md)

> 이상탐지 모델을 학습하고 서비스할 때, 실제로 계산하는 시간보다 켜 두기만 한 시간이 비용을 좌우하는가? 상시 엔드포인트 대신 서버리스·배치 추론을 고르는 기준은 무엇인가?

커리큘럼 02. AWS Infrastructure & Pricing의 학습 노트입니다. 실제 프로젝트의 이상탐지 모델은 처음에 Colab에서 학습하고 이후 AWS로 옮길 수 있습니다. 이 문서는 Amazon SageMaker AI로 옮길 때의 과금 구조를 다룹니다. Colab의 요금과 성능은 범위 밖입니다. 요율은 서울 리전 공개 On-Demand 요율이고 작업량은 가상 값입니다.

## 1. 과금 단위

| 구성 요소 | 계량 방식 (요금 페이지) | 서울 리전 요율 예 |
|---|---|---|
| 노트북 인스턴스 | 선택한 인스턴스 유형의 사용 시간 | ml.t3.medium **0.062 USD/시간**, ml.g4dn.xlarge 0.906 USD/시간 |
| 노트북 ML 스토리지 | GB-월 | gp2 **0.1596 USD/GB-월** |
| 학습 작업 | 선택한 인스턴스 유형의 사용량 | ml.m5.xlarge 0.283, ml.g4dn.xlarge **0.906**, ml.g5.xlarge **1.54625** USD/시간 |
| 학습 ML 스토리지 | GB-월 | gp2 0.1596 USD/GB-월 |
| 실시간 엔드포인트 | 선택한 인스턴스 유형의 사용량. 요청이 없어도 인스턴스가 떠 있으면 과금 | ml.m5.large **0.142 USD/시간**, ml.g4dn.xlarge 0.906 USD/시간 |
| 엔드포인트 데이터 처리 | 들어오고 나간 GB | 각각 0.016 USD/GB |
| 서버리스 추론 | 요청 처리에 쓴 컴퓨팅을 **밀리초 단위**로 과금, 메모리 설정에 따라 요율이 다름 | 1 GB 0.00002, 2 GB **0.00004**, 4 GB 0.00008 USD/초 |
| 배치 변환 | 선택한 인스턴스 유형의 사용 시간 | 학습·호스팅과 같은 인스턴스 요율 체계 |

- 학습 작업의 초 단위 과금 여부와 관리형 Spot 학습의 할인 조건은 이번에 확인한 요금 페이지에서 찾지 못했습니다(요금 페이지의 초 단위 과금 문장은 Data Wrangler 작업, Spot 문장은 HyperPod에 대한 것). 실험에서는 학습 시간을 시간 단위 연속값으로 계산하고, Spot은 계산에 넣지 않습니다.
- JupyterLab 공간은 공간이 실행 중일 때만 컴퓨팅을 과금하고, 스토리지는 **공간을 삭제할 때까지** 과금합니다. 노트북 인스턴스의 중지 상태 스토리지 과금도 Price List의 별도 GB-월 항목으로 존재하므로, 컴퓨팅을 멈춰도 스토리지는 남는다고 보고 계산합니다.
- 프리 티어는 첫 SageMaker AI 자원을 만든 달부터 시작합니다. 이 문서에서는 제외합니다.

## 2. 가상 예제 — 켜 둔 시간과 쓴 시간

### 노트북

| 사용 방식 | 월 과금 시간 | 컴퓨팅 비용 | 스토리지 20 GB | 합계 |
|---|---:|---:|---:|---:|
| ml.t3.medium 상시 실행 | 720 | 44.64 USD | 3.19 USD | 47.83 USD |
| ml.t3.medium 평일 8시간만 | 176 | 10.91 USD | 3.19 USD | 14.10 USD |
| ml.g4dn.xlarge(GPU) 상시 실행 | 720 | 652.32 USD | 3.19 USD | 655.51 USD |

GPU 노트북을 실험 기간 내내 켜 두는 것이 가장 큰 유휴 비용입니다. **GPU가 필요한 시간만 학습 작업으로 분리**하면, 같은 g4dn.xlarge로 2시간 학습을 월 8회 실행해도 `16 × 0.906 = 14.50 USD`입니다. 중지해도 스토리지 3.19 USD는 남습니다.

### 추론

이상탐지 점수를 월 100,000회 요청하고, 서버리스 2 GB 설정에서 요청당 처리 시간이 200 ms라고 가정합니다.

| 방식 | 계산 | 월 비용 | 품질 조건 |
|---|---|---:|---|
| 실시간 엔드포인트 ml.m5.large 1대 | `720 × 0.142` | 102.24 USD | 항상 대기, 콜드 스타트 없음 |
| 서버리스 2 GB | `100,000 × 0.2초 × 0.00004` | 0.80 USD | 유휴 후 첫 요청에 콜드 스타트 지연 |
| 배치 변환 | 인스턴스 × 실행 시간 | 실행 빈도에 비례 | 실시간 응답 불가, 결과가 주기적으로 갱신 |

요청이 드물면 상시 엔드포인트의 비용 대부분이 유휴 시간입니다. 반대로 요청이 많고 지연 요구가 엄격하면 서버리스의 초당 요율과 콜드 스타트가 불리해집니다. 손익분기는 `월 요청 수 × 요청당 처리 시간 × 서버리스 초당 요율 = 엔드포인트 월 비용`에서 구합니다. 위 가정에서는 월 약 1,278만 회입니다. 서버리스 데이터 처리 요금, 엔드포인트 스토리지, 데이터 처리 GB는 이 비교에서 제외했습니다.

센서 이상탐지가 "몇 분마다 한 번 전체 구역 점수 계산"이라면 실시간 엔드포인트 없이 배치 처리(또는 Lambda)로 충분할 수 있습니다. **추론 결과를 누가 얼마나 빨리 써야 하는지 모르면 엔드포인트 축소 판단을 보류**합니다.

## 3. 낭비가 생기는 조건과 판단 근거

| 의심 상황 | 필요한 자료 | 보류 조건 |
|---|---|---|
| 노트북 상시 실행 | 인스턴스 상태 기간, 커널 활동·마지막 사용 시각 | 장시간 학습이 노트북 안에서 돌고 있음 |
| 엔드포인트 유휴 | 엔드포인트별 호출 수·지연(CloudWatch), 인스턴스 수·유형 | 호출 수가 0이어도 장애 대비 대기 요구가 있음 |
| GPU 과다 | 학습 작업의 GPU 사용률·학습 시간, 같은 모델의 CPU 학습 시간 | CPU와 GPU의 결과 품질(정확도) 비교가 없음 |
| 중지 후 잔존 비용 | 노트북·학습·엔드포인트 스토리지 볼륨, 모델 아티팩트(S3) | 데이터 보존 기간 규칙이 없음 |

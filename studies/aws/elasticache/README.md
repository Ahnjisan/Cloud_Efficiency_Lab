# Amazon ElastiCache 비용 산정 01 — 노드 시간, 서버리스 최소 저장량, ECPU

[AWS 서비스 목차](../README.md) · [누수 패턴 방법 노트](../../methods/cost-leak-patterns.md) · [실험 035 — 축출 정책](../../../experiments/035-cache-eviction-policy/README.md)

> 데이터가 50 MB뿐인 작은 캐시를 서버리스로 만들면 엔진 선택만으로 비용이 15배 달라질 수 있는가? 노드 방식과는 어디서 갈리는가?

요율은 **AWS Price List 서울 리전 온디맨드 공개 요율**([2026-11-15 사본](../../../references/aws-price-list-apn2-2026-11-15.json), AmazonElastiCache 게시일 2026-11-13)이고, 작업량은 가상 값입니다. 한 달은 730시간입니다.

## 1. 과금 단위

| 방식 | 항목 | 계량 | 서울 요율 (Valkey / Redis OSS) |
|---|---|---|---|
| 노드 | 노드 시간 | **부분 시간도 1시간으로 과금** | cache.t4g.micro 0.0192 / 0.024, t4g.small 0.0376 / 0.047, m7g.large 0.1536 / 0.192 USD/시간 |
| 서버리스 | 데이터 저장 | GB-시간. **최소 저장량: Valkey 100 MB, Redis OSS·Memcached 1 GB** | 0.101 / 0.151 USD/GB-시간 |
| 서버리스 | ECPU | 요청이 전송하는 데이터 **1 KB마다 1 ECPU** | 0.0027 / 0.0041 USD/100만 ECPU |
| 공통 | 백업 | GB-월 | 0.085 USD/GB-월 |

Memcached 노드 요율은 Redis OSS와 같습니다. 서버리스의 "1 KB마다 1 ECPU"를 올림으로 셀지(예: 1.2 KB → 2 ECPU)는 문서 문장으로는 명확하지 않아 아래 예제에서는 KB 단위 정수 크기만 씁니다.

## 2. 가상 예제 — 데이터 50 MB, 월 1,000만 요청(각 1 KB 이하)

| 구성 | 계산 | 월 비용 |
|---|---|---:|
| 서버리스 Valkey | 최소 0.1 GB × 0.101 × 730 + 10 × 0.0027 | **7.40 USD** |
| 서버리스 Redis OSS | 최소 1 GB × 0.151 × 730 + 10 × 0.0041 | **110.27 USD** |
| 노드 Valkey t4g.micro 1대 | 0.0192 × 730 | 14.02 USD |
| 노드 Valkey t4g.micro 2대(복제본 1) | 2 × 0.0192 × 730 | 28.03 USD |
| 노드 Redis OSS t4g.micro 1대 | 0.024 × 730 | 17.52 USD |

- 데이터 50 MB는 두 엔진의 최소 저장량보다 작으므로 실제 데이터와 무관하게 최소치가 과금됩니다. Redis OSS 서버리스는 실제 데이터의 20배(1 GB)를 내는 셈입니다.
- 요청 크기가 3 KB로 커지면 ECPU가 3배가 되지만 Valkey 서버리스 합계는 7.45 USD로, 이 규모에서는 저장 최소치가 비용 대부분입니다.
- 노드 방식은 사용량과 무관한 상시 비용입니다. 짧게 띄웠다 내리는 테스트 노드는 몇 분만 써도 1시간이 과금됩니다.

## 3. 낭비가 생기는 조건과 판단 근거

1. **작은 데이터에 Redis OSS·Memcached 서버리스**: 저장량 지표(`BytesUsedForCache`)가 1 GB보다 훨씬 작으면 최소치가 비용을 결정합니다. 엔진 호환성(사용하는 명령, 클라이언트 라이브러리)을 확인하지 못하면 엔진 변경은 **판단 보류**입니다.
2. **과대 노드**: 메모리 사용률과 축출(`Evictions`) 수를 함께 봅니다. 축출이 많으면 줄일 수 없고, 축출 정책에 따라 적중률이 달라집니다([실험 035](../../../experiments/035-cache-eviction-policy/README.md)).
3. **캐시가 원본보다 비싼 경우**: 캐시 적중으로 줄어드는 원본(DB 읽기, LLM 호출 등) 비용이 캐시 비용보다 작으면 손해입니다. 적중률과 원본 1건당 비용이 판단 자료입니다.

## 4. 확인 문제

1. 서버리스 Valkey에 데이터 500 MB를 저장하면 저장 요금은 얼마인가요?
2. 테스트용 노드를 10분씩 하루 3번 띄우면 노드 시간은 몇 시간으로 계산되나요?
3. 캐시 적중률만 보고 노드 크기를 줄여도 되나요?

## 5. 확인 범위와 다음 질문

노드 부분 시간 올림, 서버리스 최소 저장량과 ECPU 정의는 요금 페이지에서 확인했습니다. ECPU의 소수 KB 올림 방식, 명령별 추가 ECPU(복잡한 명령은 더 많은 ECPU를 쓸 수 있음)는 세부 규칙을 확인하지 않았습니다(**미확인**).

## 확인 문제 정답과 해설

1. 0.5 × 0.101 × 730 = 36.87 USD입니다. 최소치(100 MB)를 넘으므로 실제 저장량으로 계산합니다.
2. 3번 모두 부분 시간이므로 하루 3시간으로 계산됩니다. 30분 미만으로 여러 번 띄우는 테스트는 한 번에 몰아서 하는 편이 쌉니다.
3. 안 됩니다. 적중률은 남은 메모리와 축출 정책, 접근 패턴에 따라 달라집니다. 메모리 사용률·축출 수와 원본 비용을 함께 봐야 합니다.

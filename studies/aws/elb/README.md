# Elastic Load Balancing — 시간료와 용량 단위

[AWS 서비스 목차](../README.md)

로드 밸런서를 통한 연결과 요청은 대상 서버의 CPU 비용과 별도다. [네트워크 흐름](../../foundations/network-and-data-flow.md)으로 과금 경계를 표시한다.

## ALB와 NLB

ALB는 HTTP 계층에서 경로 등의 규칙으로 대상 그룹에 요청을 보낸다. NLB는 전송 계층 연결을 대상에 분산하며 리스너 프로토콜에 따라 용량 기준이 달라진다. 대상 그룹과 상태 확인은 어디로 보낼지 결정한다. 시간료에 용량 단위 사용료가 더해진다. ALB LCU는 신규 연결, 활성 연결, 처리 바이트, 규칙 평가의 시간별 환산값 중 최대가 기준이다. NLB의 기본 사용량 과금은 신규 연결·흐름, 활성 연결·흐름, 처리 바이트를 프로토콜에 해당하는 기준으로 환산하고 해당 시간의 세 차원 중 가장 높은 NLCU만 사용한다. 용량 예약을 사용하면 예약량과 초과 사용량의 과금 조건을 별도로 확인한다.

## 가상 비교

ALB의 어느 한 시간 환산값이 순서대로 0.4, 0.5, 2, 0.3 LCU라면 최대 2를 적용한다. 가상 $0.025/시간과 $0.01/LCU·시간을 적용하면 $0.045다. 규칙 평가가 0.1로 줄어도 바이트가 지배하면 이 시간의 LCU는 같다. 유휴 환경도 프로비저닝 시간료를 확인하며, 통합 시 장애 범위·TLS·라우팅·가용성을 검토한다. CloudWatch와 액세스 로그로 지배 차원을 좁히고 전송 및 공인 IPv4 등 별도 항목은 비용 데이터에서 대조한다.

NLB에서도 TCP 트래픽만 있는 한 시간의 세 차원 환산값이 각각 0.4, 0.5, 2 NLCU라면 청구 사용량은 2 NLCU다. 한 시간의 로드 밸런서 시간료에 2 NLCU의 사용료를 더한다.

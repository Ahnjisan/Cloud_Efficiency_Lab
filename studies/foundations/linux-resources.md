# Linux 자원 — CPU·메모리·디스크 관측

[공통 비용 기초](README.md)에서 구분한 할당량과 실제 사용량을 Linux 프로세스 단위로 살펴본다. 목표는 부하가 늘 때 어느 자원이 먼저 제약되는지 설명하는 것이다.

## 실행과 메모리

프로세스는 주소 공간과 열린 파일 등의 실행 자원을 가진다. 같은 프로세스의 스레드는 주소 공간을 공유하며 실행 흐름과 스택을 각각 갖는다. 스케줄러는 실행 가능한 스레드에 CPU 시간을 배분한다. 문맥 전환은 실행 상태를 저장하고 복원하는 작업이므로 실행 가능한 스레드가 과도하게 늘면 처리량이 오히려 떨어질 수 있다. CPU 사용률의 분모가 코어 한 개인지 전체인지 먼저 확인한다.

가상 주소 공간은 매핑을 포함하고 RSS는 현재 물리 메모리에 상주하는 부분을 추정한다. 공유 페이지가 각 프로세스 RSS에 잡힐 수 있으므로 RSS를 합산해 시스템 전체 사용량으로 해석하면 어긋난다. 파일의 페이지 캐시는 재사용을 빠르게 하고 필요 시 일부 회수할 수 있다. 스왑이 있으면 메모리 압력에서 페이지 이동으로 지연이 커질 수 있으며, 회수가 실패하면 커널 또는 cgroup 범위에서 OOM으로 프로세스가 종료될 수 있다.

## 격리와 관측 순서

네임스페이스는 PID·네트워크 등 프로세스가 보는 범위를 분리하고 cgroup은 프로세스 그룹의 자원을 계측·제어한다. 파일 시스템 캐시 때문에 애플리케이션 쓰기 완료 시점과 장치 쓰기 완료 시점은 다를 수 있다. `top`, `/proc/PID/status`, `vmstat`, `iostat`, cgroup v2의 `cpu.stat`·`memory.events`를 같은 시간대에서 대조한다. CPU가 낮고 저장 장치 대기와 애플리케이션 지연이 함께 오르면 디스크 병목 후보를 먼저 확인한다.

가상 4 vCPU에서 10초간 누적 CPU 시간이 12 CPU-초라면 전체 용량 대비 12/(4×10)=30%다. 단일 스레드가 10초 내내 실행되었어도 이 평균에 가려질 수 있다. CPU 축소는 코어별 피크, 스로틀링, 지연, 다음 피크까지 확인한 뒤 판단한다.
